## 一、问题的真正根因

对比示范实现（`dsh-model-visibility` 0.2.1）与本插件，**状态模型不同**：

### 示范实现（正确）

```js
async toggle(provider, model, name, hidden) {
  const current = this.form.getSnapshot().value?.hidden ?? []
  await this.write(this.nextHidden(current, provider, model, name, hidden))
}
async write(next) {
  await this.form.set('hidden', next)   // 只写一个字段
  await this.load()                     // 写完重读目录
}
```

要点：
1. **`hidden` 是唯一状态源**，每次操作都从 `form.getSnapshot()` 取当前值再算新值；
2. **只写一个字段**，一次广播；
3. 写完重读目录 —— 这是**安全的**，因为目录只用来**渲染行**，不承担状态；
   隐藏的模型不在目录里，其行由 `hidden` 条目本身重建（条目带 `name` 快照）。

### 本插件（错误）

1. 用**本地 `store.rows` 当状态源**，`apply()` 修改它、`write()` 再写出去；
2. **一次保存写两个字段**（`hidden` + `renamed`），宿主每次写入都广播 →
   竞态窗口翻倍；
3. 保存后 `await this.load()` **用目录覆盖本地 rows** —— 目录已按隐藏列表过滤，
   读到的是旧状态，于是把用户刚做的单点修改盖掉。

**这解释了两个现象**：
- 单点隐藏失效（改动量小，被覆盖后看不出痕迹）；
- 页面回到顶部（`store.rows` 被换成新数组，列表重挂）。

批量按钮当时"看着正常"，是因为它一次改动大量行，覆盖后差异不明显。

## 三、保留的增量功能

示范实现没有、本插件要保留的：

- **备注名**（`renamed` 字段）：给模型改显示名；
- **Star 入口**（标题行右侧）；
- **加载/错误态仍显示页头**。

这些都在稳定状态模型之上追加，不改变 `hidden` 的写入路径。

## 四、验收标准

1. 单个开关点击后**立即生效且保持**，刷新页面后仍生效；
2. 批量隐藏后，单独打开任一项**生效**；
3. 任何操作**不导致页面滚动位置丢失**；
4. 渠道分组折叠可用（若实现折叠）；
5. UI 布局与示范实现一致：一屏内按渠道分组展示，每行一个开关；
6. DSH 里加载的确实是新版本（验证文件指纹）；
7. 全部测试通过。
