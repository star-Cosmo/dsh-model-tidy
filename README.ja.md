# dsh-model-tidy

[中文](README.md) · [English](README.en.md) · **日本語** · [Русский](README.ru.md)

DeepSeek Harness のモデル選択メニューを整理するプラグインです。どのモデルを表示するかを選び、覚えやすい名前を付け、使いやすい順序に並べ、プロバイダーが表示名に付けている従量倍率を保ちます。オプションの可用性確認もあり、あるモデルが今も動くかを確かめられます。

![モデル整理の設定画面](docs/screenshots/main.png)

## 解決する問題

プロバイダーのプラグインを二つ三つ入れると、モデルメニューは壁になります。無料枠のレーン、作業用アプリ、自分で設定したゲートウェイ——気づけば三十項目。そのほとんどは選ぶことのないモデルで、いくつかは同じモデルが別の経路で重複しています。

モデル選択は**意思決定の場であって、在庫一覧ではありません**。実際に使ういくつかだけを、見覚えのある名前で、自分で決めた順序で並べるべきです。

## できること

インストールすると、DSH の設定に「**モデル整理**」セクションが追加されます。モデルは取得元のプロバイダーごとにまとまり（プロバイダーごとに一枚のカード）、それぞれに一つのスイッチが付きます。

```
┌─ WorkBuddy ─── 8/12 ─ [順序を戻す] [全て隠す] [全て表示] ─┐
│ ▲▼  Auto                                         ●───    │
│ ▲▼  GLM-5.3 · x0.79                              ●───    │
│ ▲▼  GLM-5.2 · x0.79 · 夜間割引      ● [別名]     ───●    │
│ ▲▼  Grok-4.7 · x1.90                               ───●    │
└──────────────────────────────────────────────────────────┘
┌─ our-free-model ─ 6/6 ─ [順序を戻す] [全て隠す] [全て表示] ─┐
│ ▲▼  Kilo Auto Free                                 ●───    │
└──────────────────────────────────────────────────────────┘
```

- **モデルごとに一つのスイッチ** — オフにするとモデル選択メニューから消えます。
- **上下矢印（`▲▼`）** — プロバイダーのカードと、その中のモデルを並べ替えられます。ヘッダーのボタンで既定の順序に戻せます。
- **別名** — 覚えやすい名前を付けると、選択メニューはその名前で表示します。プロバイダーの従量倍率は末尾にそのまま残ります。
- **検索** — モデル名・プロバイダー・別名で絞り込めます。
- **プロバイダー単位の一括操作** — 一つのプロバイダーの全モデルをワンクリックで隠す／表示する。
- **全体の表示／非表示** — カタログ全体に対する二つのボタン。
- **可用性確認** — 表示中のモデルが今も動くかを一行ずつ確認し、行ごとに状態ドットを付けます。
- **復元** — 別名をすべて消すボタンと、全モデルを戻すボタン。

## 並び順のカスタマイズ（モデル）

各行の左にある二つの矢印で、そのプロバイダー内の順序を入れ替えられます。順序は**明示的に保存**されるため、DSH を再起動しても、設定を他のマシンに同期しても残ります。

- **順序と表示は別** — 並べ替えたモデルを隠しても、保存された順序の中に位置が残り、再表示すると元の場所に戻ります。
- **新しいモデルは並べた後ろに付く** — プロバイダーが後から追加したモデルが、手間をかけて並べた列の途中に割り込むことはありません。
- **絞り込み中でも並べ替えられる** — 検索中に矢印を押すと、**現在見えている隣**と入れ替わるので、押した結果が必ず見えます。絞り込みで隠れている行は、それぞれの相対位置を保ちます。
- **ワンクリックで取り消し** — ヘッダーの「順序を戻す」で、そのプロバイダーのカスタム順序を破棄し既定の並びに戻ります。

## 並び順のカスタマイズ（プロバイダー）

プロバイダーのカードにも一組の矢印が付いており、よく使うチャネルを一番上に移動できます。チャネルの順序は**別のフィールド（`providerOrder`）に保存**され、セッションとは無関係で、再起動後も残ります。

- **動かしたものだけが移動する** — 自分で動かしていないチャネルや、後から登録されたプロバイダーは元の位置を保ち、並べたものの後ろに付きます。
- **内部の順序とは独立** — チャネルを移動しても、各プロバイダー内のモデル順序は乱れません。
- **ワンクリックで取り消し** — ツールバーの「チャネルの順序を戻す」で、harness の既定の並びに戻ります。

## 可用性確認

モデル選択メニューは「モデルが**一覧にある**」ことしか教えてくれません——今動くかどうかは教えてくれません。プロバイダーをいくつか入れると、退役したモデルや死んだゲートウェイの経路は黙って消えたりしません。

「可用性を確認」を押すと確認ダイアログが開き（少量のトークンを消費します）、**表示中**の各モデルに一度だけ小さなリクエスト（一字だけを求める）を送ると説明します。すると各行に状態ドットが付きます。

- **緑** = 利用可能
- **赤** = 利用不可（ホバーで遅延と失敗理由が見られます）
- **黄** = 検査中
- **灰** = 未検査

検査はホスト側で行われ（モデル呼び出しはホストにしかないため）、フロントエンドはモデルを一括してループバック専用ルートに渡し、ホストが限られた同時実行数（幅 4、モデルあたり 8 秒のタイムアウト）で個別に検査して、各判定を自分の行に戻します。途中で停止もできます。非表示のモデルは検査されず、結果はメモリ内にのみ保持されます——可用性は「この瞬間」の真実であり、次のセッションのために古い判定として保存はされません。

## 別名を付けても従量倍率は失われません

プロバイダーは従量倍率をモデルの**表示名**に付け足します——`GLM-5.3 · x0.79` のように。harness のモデルカタログに倍率のフィールドがないためです。この名前をそのまま置き換える（よくある別名の実装）と、倍率は黙って失われます。

本プラグインはプロバイダー自身の区切り文字で名前を分割し、後半を保ちます。

| | 選択メニューに表示される名前 |
|---|---|
| プロバイダーの元の名前 | `GLM-5.3 · x0.79` |
| 「GLM 安い」に別名変更 | **`GLM 安い · x0.79`** |
| セール表示付きで別名変更 | **`GLM 安い · x0.79 · 夜間割引`** |
| 倍率がないモデルを別名変更 | `自動` ← 余分な区切りは付かない |

## 隠してもモデルの位置は動きません

隠したモデルはカタログに存在しません（harness が取り除きます）。そのため行は保存された情報からしか復元できません。**素直に末尾へ追加すると、隠した瞬間にグループの一番下へ飛びます**。本プラグインは各行を最初に見た位置を覚えているので、五つのうち三つ目を隠しても三つ目のままです。

## 意図的にやらないこと

**整理は表示上の判断であり、設定の変更ではありません。**

- プロバイダーの設定は書き換えません。非表示リスト、別名表、並び順の記録は本プラグイン自身の設定名前空間にのみ存在します。
- 使用中のモデルを隠したり別名を変えても、そのセッションは動き続けます。経路はモデル ID で決まり、変わるのは表示名だけです。
- アンインストールすると元の一覧に完全に戻ります。
- プロバイダーが新しく提供し始めたモデルは既定で表示されます。本プラグインが記録するのは「何を隠すか」「何を改名するか」「何を並べるか」だけで、「何を表示するか」ではありません。

## 対象範囲

スイッチは**すべての**モデル取得元に効きます。手動設定のプロバイダーだけではありません。本プラグインが絞り込むのは harness 自身のカタログ列挙——`ctx.llm.listModels` と `ctx.llm.listProviders`——であり、これはすべての画面が読む一覧です。他のプラグインが `ctx.llm.registerAdapter` で登録したモデルも、`llm-pi-ai` で宣言されたプロバイダーも、同じ一覧に入るため対象になります。

行は **プロバイダー + モデル** をキーとするため、同じモデル名が二つの経路から来ても独立した二行のままです。`workbuddy/gemini-3.8-flash` と `gemini/gemini-3.8-flash` は別の上流サービスであり、それぞれにスイッチと別名があります。

## インストール

```sh
dsh plugin --profile <あなたの profile> add dsh-model-tidy
```

その後 DSH Web GUI を開き直すと、設定ナビゲーションに「**モデル整理**」が現れます。

> 可用性確認にはホストの Web サービスが必要です。対応していない環境でも整理機能はそのまま使えますが、検査ボタンだけは表示されません。

## 開発

ビルド手順はありません。両方とも harness がそのまま読み込む素のファイルとして配布されます。ホスト側は ES モジュール、ブラウザー側は `window.__ModuleLoader__.load` ファクトリー——クライアントのモジュールシステムが呼ぶ形式です。

```sh
npm test
```

十三のスイートをまとめて実行します。カタログのフィルター、従量倍率の分割、ブラウザー側の挙動、別名の後尾の取り込み、行の並び順、モデルの並べ替え、プロバイダーの並べ替え、並び順と描画、可用性の検査、検査の速度、検査の描画、描画ツリー、そして同じメソッドを包む別プラグインとの共存です。

`npm run check:packaging` は、クライアント依存の宣言が harness に実在するパッケージを指しているかを検証します。

## 互換性

DSH `0.2.0-rc.2` に対して開発しています。DSH `>= 0.2.0-rc.1` が必要です——このバージョンで設定層に `configForms` サービスが加わり、本プラグインのセクションはそれを通して書き込みます。
